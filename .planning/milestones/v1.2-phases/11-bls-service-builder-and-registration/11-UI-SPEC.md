## Layout Contract

### SubmitEditor -- Algorithm Selector Addition (BLS-01)

The new Signature Algorithm dropdown is inserted inside the existing aggregator options panel (`bg-charcoal-dark` nested surface), between the existing Submit Type dropdown and the Signature Prefix dropdown.

```
+--------------------------------------------------------------+
| Submit Type: [Aggregator v]                                   |
|                                                                |
| +----------------------------------------------------------+  |
| | (aggregator options panel - bg-charcoal-dark)            |  |
| |                                                          |  |
| | Signature Algorithm                                      |  |
| | [ECDSA (secp256k1) v]                                    |  |
| |                                                          |  |
| | Signature Prefix                                         |  |
| | [EIP-191 v]  (auto-set to "None" when BLS selected)     |  |
| |                                                          |  |
| | Component [...]                                          |  |
| +----------------------------------------------------------+  |
+--------------------------------------------------------------+
```

Layout rules:
- Algorithm dropdown: `flex flex-col gap-2` (label + dropdown, matches Signature Prefix pattern)
- Inserted as first child of the aggregator panel, above Signature Prefix
- Aggregator panel: existing `flex flex-col gap-4 p-4 rounded bg-charcoal-dark border border-charcoal-light`
- Only visible when Submit Type is "Aggregator" (existing conditional)

### ServiceDeploy -- Post-Deploy BLS Key Display (BLS-02)

After all three deploy steps complete successfully AND the service uses BLS algorithm, a new card appears below the deploy progress card.

```
+--------------------------------------------------------------+
| Deploy Progress                                               |
|   1. Upload to IPFS                              Done         |
|   2. Set Service URI on-chain                    Done         |
|   3. Register with WAVS                          Done         |
+--------------------------------------------------------------+
|                                                                |
| +----------------------------------------------------------+  |
| | BLS Operator Key                                         |  |
| | 0x1234...5678 [copy]                                     |  |
| |                                                          |  |
| | Register this key on-chain from the service detail page. |  |
| +----------------------------------------------------------+  |
|                                                                |
| [Deploy Service]  (disabled after completion)                  |
+--------------------------------------------------------------+
```

Layout rules:
- BLS key card: `p-4 rounded bg-charcoal-medium border border-charcoal-light`
- Heading: `text-beige-warm text-sm font-medium mb-2`
- Helper text: `text-tan-muted text-xs mt-2`
- Positioned in the existing `flex flex-col gap-6` between deploy progress and deploy button
- Only rendered when: all deploy steps are "done" AND `signatureAlgorithm === 'bls12381'`

### ServiceDetailPage -- BLS Registration Status and Action (BLS-03, BLS-04)

A new section is added within the existing header card, below the contract info grid and above the actions bar. Only visible for BLS services.

```
+--------------------------------------------------------------+
| My BLS Service                           [Active] [Owner]     |
|                                                                |
| Chain: evm:31337     Address: 0xabcd...1234 [copy]           |
| Owner: 0x1111...2222  Total Weight: 100                       |
| Threshold: 50          Quorum: 67/100 (67.0%)                |
|                                                                |
| +----------------------------------------------------------+  |
| | BLS Operator Key           [Registered] / [Unregistered] |  |
| | 0x9abc...def0 [copy]                                     |  |
| +----------------------------------------------------------+  |
|                                                                |
| [Edit] [Pause]                [Register BLS Key] [Refresh]   |
| (or if registered:)          (button hidden)     [Delete]    |
+--------------------------------------------------------------+
```

Layout rules:
- BLS section: `p-3 rounded bg-charcoal-dark border border-charcoal-light mt-3 mb-1`
- Section header row: `flex items-center justify-between mb-2`
- Heading: `text-tan-muted text-xs font-semibold` ("BLS Operator Key")
- Registration badge: reuse Phase 10 `RegistrationBadge` pattern (same classes)
- Key display: `AddressDisplay` component on the second line
- "Register BLS Key" button: placed in the primary actions area (left side of actions bar), using `Button size="sm" color="purple"`
- Button only visible when registration status is "unregistered"
- While registration transaction is pending: button text changes to "Registering..." with `disabled` state

## Interaction Contract

### Algorithm Selector Behavior (BLS-01)

| Property | Value |
|----------|-------|
| Visibility | Only when Submit Type is "Aggregator" |
| Default value | `secp256k1` (ECDSA) |
| Options | "ECDSA (secp256k1)" and "BLS (bls12381)" |
| Side effect on BLS selection | Auto-set `signaturePrefix` to `'none'` |
| Side effect on ECDSA selection | No auto-change to prefix (user may have set it intentionally) |
| Persistence | Stored in `serviceBuilderStore` via `SubmitDraft.signatureAlgorithm` |

### Post-Deploy BLS Key Display (BLS-02)

| Property | Value |
|----------|-------|
| Trigger | All three deploy steps reach "done" status AND `signatureAlgorithm === 'bls12381'` |
| Data source | `getServiceSigner(manager)` to get the `bls12381.g1_pubkey_hex` field |
| Fallback | If `getServiceSigner` fails, call `deriveBlsPubkey(0)` directly |
| Display | `AddressDisplay` component with `0x` prefix prepended to hex string |
| Copy behavior | Standard `AddressDisplay` copy-to-clipboard (copies full hex value) |
| Loading state | While fetching BLS pubkey, show `text-tan-muted text-xs`: "Loading BLS key..." |
| Error state | If both fetches fail, show `text-red-3 text-xs`: "Failed to load BLS key. Check that the WAVS node is running." |

### BLS Registration Flow (BLS-03)

| Property | Value |
|----------|-------|
| Trigger | User clicks "Register BLS Key" button on service detail page |
| Pre-conditions | Service uses BLS algorithm, registration status is "unregistered", WAVS node running |
| Button states | Idle: "Register BLS Key" / In-progress: "Registering..." (disabled) |
| Step 1 | Call `getServiceSigner(manager)` to get BLS HD index |
| Step 2 | Call `blsSignProofOfPossession(hdIndex, operatorAddress)` to get G1 key + G2 proof |
| Step 3 | Call `updateBlsSigningKey(publicClient, walletClient, registryAddress, blsKeyHex, blsProofHex)` |
| Step 4 | Wait for transaction receipt, then re-check registration status |
| Success feedback | `Toast.info('BLS key registered successfully!')` + badge updates to "Registered" |
| Error feedback | `Toast.error('BLS registration failed: {error}')` + button returns to idle state |
| Operator address | `getAddress()` from `useViemClient` (HD index 0 of signing mnemonic) |

### BLS Registration Status Check (BLS-04)

| Property | Value |
|----------|-------|
| Trigger | On service detail page mount + after successful registration |
| Condition | Service algorithm is `bls12381` (detected via `isBLSService()` helper) |
| Contract call | `readContract` with `BLSPOAStakeRegistryABI.getLatestOperatorSigningKey(operatorAddress)` |
| Registered | Returned bytes length > 2 (i.e., not empty `0x`) |
| Unregistered | Returned bytes is empty `0x` or length <= 2 |
| Unknown | Contract call throws an error |
| NOT auto-polled | Checked on mount and after registration only (too expensive for polling) |
| ABI selection | Must use `BLSPOAStakeRegistryABI` (returns `bytes`), NOT `POAStakeRegistryABI` (returns `address`) |

### Copy-to-Clipboard

| Property | Value |
|----------|-------|
| Component | `AddressDisplay` (reused) |
| Truncation | Default `first6...last4` for BLS G1 pubkey hex strings |
| Hover | Copy icon appears on hover (existing behavior) |
| Confirmation | Checkmark icon for 1.5 seconds (existing behavior) |
| Full value | Accessible via `title` attribute on hover (existing behavior) |
| Prefix | BLS pubkey displayed with `0x` prefix: `0x${g1_pubkey_hex}` |

## State Mapping

| UI Element | Data Source | Update Mechanism |
|------------|------------|------------------|
| Algorithm selector value | `serviceBuilderStore.submit.signatureAlgorithm` | Zustand store (user selection) |
| Signature prefix (auto-set) | `serviceBuilderStore.submit.signaturePrefix` | Zustand store (auto-set on BLS selection) |
| Post-deploy BLS pubkey | `getServiceSigner(manager)` or `deriveBlsPubkey(0)` | One-time fetch after deploy completes |
| BLS service detection | `service.workflows[wf].submit.aggregator.signature_kind.algorithm` | Computed from service object |
| BLS registration status | `BLSPOAStakeRegistryABI.getLatestOperatorSigningKey(operator)` via viem | On mount + after registration |
| BLS operator key on detail page | `getServiceSigner(manager)` -> `bls12381.g1_pubkey_hex` | On mount |
| Operator EVM address | `getAddress()` from `useViemClient` (HD index 0) | Already available |
| BLS HD index | `getServiceSigner(manager)` -> `bls12381.hd_index` | On mount |
