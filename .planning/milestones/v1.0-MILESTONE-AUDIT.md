## Critical Gap

### MISSING-01: Bootstrap Address Format Mismatch

**File:** `packages/layer-tests/src/e2e/handles.rs:start_wavs_remote_mode():201-243`
**Affects:** NET-01, INT-02
**Severity:** Critical (E2E multi-operator Remote mode broken)

The `start_wavs_remote_mode()` function in the test harness polls `get_p2p_status()` on operator 0 and uses `status.listen_addresses.first()` to get the bootstrap address. This returns a raw socket string (`"0.0.0.0:9000"`). It then passes this verbatim to downstream operators as a bootstrapper string in `P2pConfig::Remote.bootstrappers`.

However, `parse_bootstrapper()` in `p2p.rs` requires `"<hex_pubkey>@<host>:<port>"` format. The `status.local_peer_id` field (which contains the hex pubkey) is available on the same `P2pStatus` struct but is **never read** in this function.

**Effect at runtime:**
- `parse_bootstrapper("0.0.0.0:9000")` fails (no `@` separator)
- Error logged at WARN level, bootstrapper skipped silently
- Operators 1+ start with zero bootstrappers, never discover operator 0
- Multi-operator E2E tests in Remote mode get zero connected peers → assertions fail

**Fix required:**

```rust
// In start_wavs_remote_mode(), replace:
let addr = status.listen_addresses.first().cloned();

// With:
let bootstrap_addr = match (status.local_peer_id, status.listen_addresses.first()) {
    (Some(peer_id), Some(socket_addr)) => {
        // Replace 0.0.0.0 with 127.0.0.1 for local testing
        let port = socket_addr.split(':').last().unwrap_or("9000");
        Some(format!("{}@127.0.0.1:{}", peer_id, port))
    }
    _ => None,
};
```
