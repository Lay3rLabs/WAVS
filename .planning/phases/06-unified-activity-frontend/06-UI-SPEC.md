## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, dot badge sizing, inline pill padding (px-1.5 / py-0.5) |
| sm | 8px | Compact row gaps (gap-2), child card left indent |
| md | 16px | Card internal padding (pl-3 pr-4 pt-3 pb-3 ≈ 12–16px), toolbar gaps |
| lg | 24px | Section separation, toolbar bottom border margin (pb-4 mb-4) |
| xl | 32px | Feed container padding |
| 2xl | 48px | Empty-state vertical padding (py-12) |
| 3xl | 64px | Page-level layout spacing |

Exceptions:
- Status dot badge: 6px diameter (w-1.5 h-1.5) — between xs and sm, intentional for inline indicators
- Touch/click targets on filter tabs: minimum 28px height (py-1.5 + text-xs) — acceptable for dense feed toolbar

## Typography

All sizes match the existing ActivityCard and ActivityFeed type scale. Do not introduce new sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / detail rows | 12px (text-xs) | 400 (normal) | 1.5 (leading-relaxed) |
| Label / pill text | 10px (text-[10px]) | 700 (bold) | 1.2 |
| Service name / summary | 12px (text-xs) | 400 (normal) | 1.4 |
| Mono / raw data | 12px (text-xs font-mono) | 400 (normal) | 1.625 (leading-relaxed) |

Heading sizes are not used inside the activity feed. Page-level headings follow existing page shell conventions and are out of scope for this phase.

## Color

All values from tailwind.config.js custom palette. No new colors may be introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #222020 (charcoal-dark) | Card background, feed background |
| Secondary (30%) | #2D2A2A (charcoal-medium) | Toolbar background, expanded raw JSON panel bg (charcoal-darkest #1E1E1E) |

Accent reserved for: active filter tab highlight only, "new items" floating badge only. Not used for card borders, status dots, or submission states.

Status dot colors (semantic, not accent):
- Pending indicator dot: amber-400 (#FBBF24) — pulsing animation via existing `glow-amber` keyframe
- Error badge dot: red-400 (#F87171) — pulsing animation via existing `glow-red` keyframe
- Success/complete: no persistent dot — card returns to normal border state

Trigger-type accent borders and pills are unchanged from existing code (indigo, violet, cyan, amber, sky, emerald).

Replaces the flat ActivityCard in the feed. Renders one grouped event (trigger + optional submission child).

**Collapsed state — trigger with pending submission:**
```

│ [Trigger] [EvmContractEvent pill]  ● (amber pulse)  HH:MM:SS.mmm │
│ service-name / workflow-id                                         │
│                                               [expand ▼]         │
└────────────────────────────────────────────────────────┘
```
- Amber pulsing dot (w-1.5 h-1.5 rounded-full bg-amber-400 animate-glow-amber) sits immediately after the kind pill
- No child card rendered in collapsed state

### Expand / Collapse Interaction

- Toggle target: the entire card header row is clickable (not just the "Raw ▼" label)
- Expand button text changes to "▲" when expanded, "▼" when collapsed — consistent with existing ActivityCard pattern
- Child card's raw JSON toggle is independent of parent expand
- No CSS transition animation on expand/collapse — match existing code which renders content conditionally without transition
- expandedIds Set held in ActivityFeed parent (existing lifted state pattern) — group cards keyed by correlationId, not individual item id

## Filter Tabs

Replace existing kind-filter tabs (`all | trigger | submission`) with status-based tabs.

| Tab label | Filter logic |
|-----------|-------------|
| All | Show all grouped events |
| Pending | Groups where trigger exists but no submission has arrived yet |
| Failed | Groups where submission_failed exists (whole group card visible) |
| Complete | Groups where a successful submission is present |

Tab styling: unchanged from existing pattern — `px-3 py-1.5 text-xs font-medium`, active state `bg-purple-1 text-cream-light`, inactive `bg-charcoal-dark text-tan-muted hover:text-beige-warm hover:bg-charcoal-medium`.

Tab order in DOM: All | Pending | Failed | Complete (left to right).

"Failed" tab label is plain text — no badge count. Count shown in the existing `N items` counter at toolbar right edge.

## Data Model Contract

Internal interface for grouped events (Claude's Discretion area from CONTEXT.md):

```typescript
interface GroupedActivityEvent {
  // The trigger item (always present in a group)
  trigger: ActivityItem;
  // The submission or submission_failed item, if arrived
  submission?: ActivityItem;
  // Derived display state
  status: 'pending' | 'complete' | 'failed';
  // Key for virtualizer and expandedIds
  groupKey: string; // correlationId if present, else String(trigger.id)
}
```

Grouping algorithm (useMemo in ActivityFeed):
1. Iterate flat activityList once, building a Map keyed by correlationId
2. Triggers without correlationId become standalone groups (groupKey = String(trigger.id))
3. Submissions without a matching trigger become orphan standalone cards
4. Status derived: no submission → 'pending'; submission kind === 'submission_failed' → 'failed'; else → 'complete'

## Implementation Notes for Executor

1. **Do not change the virtualizer setup** — TanStack Virtual with measureElement ref must remain. GroupedActivityEvent replaces ActivityItem as the array element type passed to the virtualizer.
2. **expandedIds keyed by groupKey** — change from `Set<number>` (item id) to `Set<string>` (groupKey). Child raw panel uses a separate local state within GroupedActivityCard.
3. **Existing `ActivityCard` retained** — used for orphan submissions only. GroupedActivityCard wraps it internally for the child submission panel.
4. **Both surfaces use the same ActivityFeed** — ServiceActivity.tsx passes `serviceId` prop; the grouping logic runs identically, only the pre-filter changes.
5. **Failed events never removed** — the FIFO 2000-cap in appStore operates on the raw activityList. Failed events are excluded from eviction (guard: `item.kind === 'submission_failed'` skips removal). Successful events follow existing cap behavior.
6. **Pulsing dot uses existing Tailwind keyframes** — `animate-glow-amber` and `animate-glow-red` are already declared in tailwind.config.js. No new CSS required.
