## Typography

Font: Montserrat. This phase uses exactly 2 weights: 400 (regular) and 600 (semibold).

| Role | Tailwind Class | Size | Weight | Line Height | Usage |
|------|---------------|------|--------|-------------|-------|
| Body | `text-sm` | 14px | 400 | 1.5 (Tailwind default) | Service name line, detail row values, filter dropdown labels |
| Label | `text-xs font-semibold` | 12px | 600 | 1.33 | Status filter tab text, workflow ID suffix, "Raw" toggle label |
| Helper | `text-xs` | 12px | 400 | 1.33 | Detail row labels (chain, block, tx), timestamp, error message text, empty state body, tx_hash display |
| Badge | `text-[10px] font-bold uppercase tracking-wide` | 10px | 700 | 1.0 | StatusBadge ("PENDING", "CONFIRMED", "ERROR"), trigger type pill |

Note: No new page titles or display-level headings are introduced. All new UI is within the existing Activity page and ServiceActivity layouts that already have their own headings.

Layout rules:
- Outer card: `pl-3 pr-4 pt-3 pb-3 rounded-lg border border-l-4 bg-charcoal-dark transition-colors` (same as current)
- Border color by status: pending: `border-charcoal-light/30`, confirmed: `border-green-900/30`, error: `border-red-900/30`

- Service/workflow line: `mt-1 text-xs text-beige-warm truncate` with `text-tan-muted` for workflow ID (same as current)
- Detail rows: identical to current `DetailRows` component
- Submission section (new): `mt-2 px-3 py-2 rounded bg-charcoal-darkest border border-charcoal-light/30`

  - Error: header row with "Error" label (`text-red-400 text-xs font-semibold`) + timestamp, body with error message (`text-red-4 text-xs mt-1 break-words`)
- Raw toggle: `mt-2 text-xs text-tan-muted hover:text-beige-warm cursor-pointer` (same as current)

## Interaction Contract

### Unified Activity Card Status Progression (ACT-01, ACT-02)

| Property | Value |
|----------|-------|
| Initial state | Card created with `status: 'pending'` when trigger event arrives |
| Confirmed transition | Card updates in-place when matching submission event arrives; status changes to `confirmed`; submission section appears with tx_hash |
| Error transition | Card updates in-place when matching submission_error event arrives; status changes to `error`; error section appears with error message |
| Correlation | `serviceId:workflowId:deterministicKey(triggerData)` -- uses specific identifying fields from each TriggerData variant (not JSON.stringify) |
| Orphaned submission | If submission/error event arrives with no matching trigger in the map, create a new card directly with `status: 'confirmed'` or `status: 'error'` (backfill trigger data from submission payload) |
| Services with submit: 'none' | Set status to `'confirmed'` immediately on trigger (no submission expected); check `service.workflows[workflowId].submit` |
| Card height change | When status updates cause content change (tx_hash or error message appearing), the virtualizer re-measures via `virtualizer.measure()` |

### Status Filter Behavior (ACT-02)

| Property | Value |
|----------|-------|
| Default | "All" (shows all statuses) |
| Pending | Shows only `status === 'pending'` cards |
| Confirmed | Shows only `status === 'confirmed'` cards |
| Error | Shows only `status === 'error'` cards |
| Persistence | In-memory only (resets on page navigation, same as current kindFilter) |
| URL params | None -- not routed |

### Tx Hash Display (ACT-02)

| Property | Value |
|----------|-------|
| Format | `0x`-prefixed hex string, truncated to first 10 + last 8 characters with ellipsis |
| Font | `font-mono text-xs text-primary-500` |
| Copy | Not clickable/copyable in this phase (future enhancement) |
| Null tx_hash | If confirmed but no tx_hash (shouldn't happen but defensive), show "Submitted" without hash |

### Error Message Display (ACT-03)

| Property | Value |
|----------|-------|
| Container | `mt-2 px-3 py-2 rounded bg-charcoal-darkest border border-red-900/30` |
| Error label | `text-red-400 text-xs font-semibold` ("Error") |
| Error message | `text-red-4 text-xs mt-1 break-words` (full error text, word-wrapped) |
| Max height | `max-h-20 overflow-y-auto` (80px cap with scroll for very long error messages) |
| Truncation | None -- full error message displayed with scroll |

### Raw JSON Expander

| Property | Value |
|----------|-------|
| Behavior | Same as current -- toggle button shows/hides raw JSON |
| Content | Trigger data JSON + trigger config JSON (same as current) |
| Enhancement | When status is confirmed/error, also include `txHash` and `errorMessage` fields in the raw output |

### Pause/Resume

| Property | Value |
|----------|-------|
| Behavior | Identical to current -- pause snapshots the list, resume restores live data |
| Snapshot | Snapshots `activityList` (derived from map, sorted by triggerTs) |
| Status updates while paused | Status updates still apply to the map but are not visible until resume |

### Scroll Behavior

| Property | Value |
|----------|-------|
| Auto-scroll | Same as current -- auto-scroll to latest when near bottom |
| New items badge | Same as current -- floating "N new items" badge when not near bottom |
| Status update scroll | No scroll change on status update (card updates in-place) |
