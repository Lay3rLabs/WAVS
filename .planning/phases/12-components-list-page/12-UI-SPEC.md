| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding (`px-1.5 py-0.5`) |
| sm | 8px | Compact element spacing, gap between inline items |
| md | 16px | Default element spacing, card internal padding (`p-4`) |
| lg | 24px | Section padding, gap between major page sections (`gap-6`) |
| xl | 32px | Layout gaps between page regions |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used in list pages) |

Exceptions:
- Filter toggle group: `gap-0` (joined button row, no gap between pills — matches ActivityFeed status filter pattern)
- Search input horizontal padding: `px-7 py-2.5` — inherits from `TextInput` atom's own Tailwind classes, do not override

Source: Phase 11 UI-SPEC (inherited); `TextInput.tsx` padding pattern confirmed.

## Layout Contract

### Page Structure

```
<div class="flex flex-col gap-6">

  <!-- Page header -->
  <div>
    <h1 class="text-beige-light text-2xl font-semibold">Components</h1>
    <p class="text-tan-muted mt-1">
      WASM components used across all registered services.
      <span class="text-tan-muted text-sm">{N} unique component(s)</span>
    </p>
  </div>

  <!-- Search + filter controls row -->
  <div class="flex flex-col gap-3">
    <!-- Search input -->
    <TextInput
      placeholder="Search by name or digest..."
      value={search}
      onChange={setSearch}
    />

    <!-- Source-type filter pill group -->
    <div class="flex rounded-md overflow-hidden border border-charcoal-light self-start">
      {SOURCE_TYPES.map(type => (
        <button class="px-3 py-1.5 text-xs font-medium transition-colors cursor-pointer
          {active ? 'bg-purple-1 text-cream-light' : 'bg-charcoal-dark text-tan-muted hover:text-beige-warm hover:bg-charcoal-medium'}">
          {type}
        </button>
      ))}
    </div>
  </div>

  <!-- Component list OR empty state -->
  <div class="flex flex-col gap-4">
    {filteredComponents.map(([digest, usages]) => (
      <ComponentCard key={digest} digest={digest} usages={usages} />
    ))}
  </div>

</div>
```

### Card Structure (enhanced)

Each card is a `<Link>` wrapping a `<div>` — entire card surface is clickable:

```
<Link to={`/components/${digest}`} class="block">
  <div class="p-4 rounded-lg bg-charcoal-medium border border-charcoal-light
              hover:border-purple-1 transition-colors cursor-pointer">

    <!-- Row 1: source badge + digest + function-count badge -->
    <div class="flex items-center gap-2 mb-3">
      <span class="px-1.5 py-0.5 text-xs font-medium bg-charcoal-light text-beige-warm rounded">
        {sourceType}
      </span>
      <AddressDisplay address={digest} />
      <span class="ml-auto px-1.5 py-0.5 text-xs font-medium bg-charcoal-light text-beige-warm rounded">
        {functionCount} {functionCount === 1 ? 'function' : 'functions'}
      </span>
    </div>

    <!-- Row 2: source details (package / URI) — existing pattern -->
    <div class="text-sm flex flex-col gap-1 mb-3">
      {/* Registry: Package + optional Domain */}
      {/* Download: URI via AddressDisplay */}
    </div>

    <!-- Row 3: permissions summary icon row -->
    <div class="flex items-center gap-3 text-xs text-tan-muted mb-3">
      {hasNetworkAccess && <span>Network</span>}
      {hasFileSystem && <span>Filesystem</span>}
      {hasRawSockets && <span>Sockets</span>}
      {!hasNetworkAccess && !hasFileSystem && !hasRawSockets && (
        <span class="italic">No special permissions</span>
      )}
    </div>

    <!-- Row 4: used by workflows — existing chip pattern -->
    <div class="border-t border-charcoal-light pt-3">
      <p class="text-tan-muted text-xs font-medium mb-2">
        Used by {usages.length} {usages.length === 1 ? 'workflow' : 'workflows'}
      </p>
      <div class="flex flex-wrap gap-2">
        {usages.map(usage => (
          <button
            onClick={(e) => { e.preventDefault(); navigate(...) }}
            class="px-2 py-1 text-xs bg-charcoal-light hover:bg-charcoal-dark
                   border border-charcoal-light hover:border-purple-1
                   text-beige-warm rounded transition-colors">
            {usage.serviceName} — {usage.workflowId}
          </button>
        ))}
      </div>
    </div>

  </div>
</Link>
```

Note on service chip click: `e.preventDefault()` must be called before `navigate()` to prevent the wrapping card `<Link>` from also firing.

### Function Count Badge

The function count badge (`{N} functions`) is displayed on the right side of Row 1 via `ml-auto`. It displays the count from `ComponentSchema.exports` object key count. While schema data loads async, the badge is omitted (not shown as "0 functions") until the data is available.

### Permissions Summary Row

The permissions summary row (Row 3) is derived from `ComponentMetadata.permissions`. Display labels:

| Condition | Label |
|-----------|-------|
| `allowed_http_hosts !== 'none'` | "Network" |
| `file_system === true` | "Filesystem" |
| `raw_sockets === true` | "Sockets" |
| All false / none | "No special permissions" (italic) |

Display these as plain text labels separated by gap-3 spacing. Do not use icons — no icon library is available. Omit the permissions row entirely if metadata has not yet loaded (do not show placeholder).

### Source-Type Filter Pills

| Source key | Display label |
|------------|---------------|
| `registry` | "Registry" |
| `download` | "Download" |
| `digest` | "Digest" |
| `oci` | "OCI" |

The filter pill group renders only the source types that exist in the current component list plus an "All" pill at the start. Multi-select: each pill toggles independently. When "All" is active, all source types are shown. Clicking "All" clears individual selections. Clicking any source type deselects "All". Default state: "All" active (all source types shown).

Filter button group uses the joined-row pattern from `ActivityFeed.tsx`:
```
<div class="flex rounded-md overflow-hidden border border-charcoal-light self-start">
```

Active pill: `bg-purple-1 text-cream-light`
Inactive pill: `bg-charcoal-dark text-tan-muted hover:text-beige-warm hover:bg-charcoal-medium`

### Search Behavior

Use existing `TextInput` atom directly. No custom search input styling — `TextInput` provides `px-7 py-2.5 rounded border border-charcoal-light bg-charcoal-dark text-beige-warm focus:border-purple-2` already.

Filtering logic: case-insensitive match on component name/package string AND digest string. AND-combined with source-type filter.

## States Contract

### Loading State (per-card async data)

Cards are rendered from the existing synchronous `componentMap` (derived from Zustand store). Schema and metadata per component are fetched lazily. While loading:
- Function count badge: omit — do not show "0 functions" or a spinner on the badge
- Permissions row: omit — do not show a skeleton row on the card
- Cards render immediately with the synchronous data they already have (source type, digest, service usage chips)

No full-page skeleton for the list page. Data is already available from Zustand store on mount.

### No Components (zero state)

When `componentMap` is empty (no services registered):

```
<p class="text-tan-muted italic">
  No services registered yet.{' '}
  <button class="text-purple-1 hover:underline" onClick={() => navigate('/services')}>
    Add a service
  </button>{' '}
  to see its components.
</p>
```

This is the existing empty state from `ComponentsPage.tsx` — preserve it exactly.

### No Search Results

When components exist but none match the current search + filter combination:

```
<div class="flex flex-col gap-3 py-6">
  <p class="text-tan-muted text-sm">No components match your search.</p>
  <button
    class="text-xs text-tan-muted hover:text-beige-warm underline self-start"
    onClick={clearFilters}
  >
    Clear filters
  </button>
</div>
```

`clearFilters` resets both `search` to `""` and source-type filter to "All".

### Error (schema/metadata fetch failure)

Use `Toast.error(message)` — existing global toast system. Do not block card rendering. Cards continue to display synchronous data; async badge/permissions rows are silently omitted on error. No per-card error indicator.

Error toast format: `"Failed to load component data: {reason}"` (single toast per failed batch, not per component).

## Interaction Contract

### Card Navigation

- Each card is a React Router `<Link to={`/components/${digest}`}>` wrapping the card `<div>`
- The entire card surface (including padding) triggers navigation
- Service workflow chips inside the card use `e.preventDefault()` before calling `navigate()` to prevent the card link from firing simultaneously
- Hover state: card border changes from `border-charcoal-light` to `border-purple-1` via `hover:border-purple-1 transition-colors`

### Search

- Controlled `useState` for search string
- Filter applied on every keystroke (no debounce needed — list is small, all client-side)
- Clearing the input (empty string) restores full list

### Source-Type Filter

- `useState<Set<string>>` initialized to `new Set()` (empty set = "All" mode)
- Empty set means "All" pill is active and all source types visible
- Clicking a source-type pill adds/removes from the set (toggle)
- Clicking "All" pill: sets state to empty set
- When set becomes empty after toggle-off, revert to "All" active
- Filter combines with search via AND

### Async Data Fetching Strategy

On mount, call `getComponentSchema(digest)` and `getComponentMetadata(digest)` for each unique component in parallel (using `Promise.allSettled`). Store results in a `Map<digest, { schema, metadata }>` local state. Cards re-render when their entry is populated.

Do not refetch on re-render. Fetch once on page mount. No polling for schema/metadata — this data is static per digest.

### No Interactions in Phase

No modals, no confirmations, no destructive actions, no inline editing.
