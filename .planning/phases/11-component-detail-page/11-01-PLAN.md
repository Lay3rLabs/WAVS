**3. Create `app/src/hooks/useComponentDetail.ts`**:

Create a new hook that fetches both schema and metadata in parallel using `Promise.allSettled` (NOT `Promise.all` — allows partial success). The hook:

- Accepts `digest: string | undefined` (from useParams, may be undefined)
- Returns `{ schema, metadata, loading, schemaError, metadataError }`
- Uses `useState` for each piece of state
- Uses `useEffect` with `digest` dependency
- If digest is undefined, sets loading=false immediately and returns nulls
- On each settled result: if fulfilled, set data; if rejected, set error string AND call `Toast.error()` with format "Failed to load component schema: {reason}" or "Failed to load component metadata: {reason}"
- Uses a cleanup flag (`let active = true`) to prevent state updates after unmount
- NO polling — component data is immutable, single fetch on mount

Import `getComponentSchema` and `getComponentMetadata` from `'../tauri/commands'`, types from `'../types'`, Toast from `'../components/atoms'`.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | URL :digest param | accept | Digest is passed to backend which validates via ComponentDigest::from_str() (Phase 10 T-10-01 mitigation). Frontend treats it as opaque string. No XSS vector — React escapes all rendered values. |
| T-11-02 | Information Disclosure | Component schema/metadata | accept | Data is local-only (Tauri desktop app, no network exposure). Schema and metadata are not sensitive — they describe WASM component interfaces. |
| T-11-03 | Denial of Service | Large schema rendering | accept | JSON.stringify in a pre block for very large schemas could cause slow rendering. Acceptable for desktop app with known-size WASM components. |
</threat_model>
