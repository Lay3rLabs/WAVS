## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (`p-1`, `gap-1`) |
| sm | 8px | Compact element spacing (`p-2`, `gap-2`, `mb-2`) |
| md | 12px | Banner inner padding (`p-3`) |
| lg | 16px | Section padding (`p-4`, `gap-4`) |
| xl | 24px | Layout gaps (`gap-6`) |

Exceptions: `p-3` (12px) is the existing standard for inline cards and callouts in ServiceDetailPage. 12px is a multiple of 4 (4 x 3 = 12) and therefore grid-compliant. The guidance banner MUST use `p-3` to match the adjacent BLS Operator Key card. `mt-3 mb-1` spacing matches the existing BLS section pattern.

Source: ServiceDetailPage.tsx lines 763, 144; Tailwind default spacing scale

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1E1E1E` (charcoal-darkest) | Page background |
| Secondary (30%) | `#222020` (charcoal-dark) | Cards, callout backgrounds, BLS section |
| Accent (10%) | `#9D7DC5` (primary-600) | Register BLS Key button, active nav items |
| Warning | amber-700/50 border, amber-400 text | Guidance banner border and title text |
| Destructive | `#A7656F` (red-3) | Error text for failed BLS key loads |

**Focal Point:** The amber-400 banner title ("Registry Required for BLS Registration") is the primary visual anchor of the new UI added in this phase -- it draws the eye to the actionable guidance when a BLS service lacks a connected registry.

**Guidance banner color contract:**

| Element | Color | Tailwind Class |
|---------|-------|----------------|
| Banner background | `#222020` | `bg-charcoal-dark` |
| Banner border | amber-700 at 50% opacity | `border-amber-700/50` |
| Banner title text | amber-400 | `text-amber-400` |
| Banner body text | `#A89F96` (tan-muted) | `text-tan-muted` |

Rationale: Amber is the established warning/attention semantic color in this codebase. It is used for WARN log levels (`Logs.tsx:8`), pending states (`ActivityCard.tsx:30`), and degraded health (`HealthIndicator.tsx:59`). The guidance banner signals "action needed" without being an error. The `charcoal-dark` background with `border-amber-700/50` border follows the ServiceReview warning pattern (`border-yellow-700` mapped to amber for consistency with the rest of the app's amber usage).

Accent reserved for: Register BLS Key button, active navigation items, primary action buttons only.

Source: `app/tailwind.config.js`, `Logs.tsx`, `ActivityCard.tsx`, `HealthIndicator.tsx`, `ServiceReview.tsx`

## Copywriting Contract

| Element | Copy |
|---------|------|
| Guidance banner title | "Registry Required for BLS Registration" |
| Guidance banner body | "To register your BLS key on-chain, add this service's contract address as a POA registry from the Services page. The registry enables on-chain key registration and operator management." |
| Empty state (not applicable) | N/A -- this phase does not introduce new pages or lists |
| Error state: BLS key load failure | "Failed to load BLS operator key." (existing, unchanged) |
| Primary CTA | "Register BLS Key" (existing, unchanged -- only visible when registry is present and status is unregistered) |
| Destructive confirmation | N/A -- no destructive actions in this phase |

### Copywriting Rules

1. The guidance banner title MUST use `font-semibold` to distinguish it from the body paragraph.
2. The guidance banner body MUST mention "Services page" as the concrete next step -- do not use vague "somewhere in the app" language.
3. The guidance banner body MUST NOT include a clickable link or navigation action. A static text hint is sufficient per RESEARCH.md anti-pattern guidance.

Source: 13-RESEARCH.md Pattern 1 (Guidance Banner for Missing Registry), Anti-Patterns section

## Interaction Contract

### Guidance Banner Behavior

| State | What Renders |
|-------|-------------|
| `serviceBls === false` | No BLS section at all (existing behavior, unchanged) |
| `serviceBls === true && registry !== null` | BLS Operator Key card + RegistrationBadge + Register BLS Key button (if unregistered). No guidance banner. |
| `serviceBls === true && registry === null` | BLS Operator Key card (key still displays via `getServiceSigner`) + Guidance banner below the key card. No Register BLS Key button (existing guard: `blsRegStatus` stays `'unknown'` when registry is null). |

### Guidance Banner Layout

```
+---------------------------------------------------------------+
| [BLS Operator Key card - existing, unchanged]                 |
| p-3 rounded bg-charcoal-dark border-charcoal-light            |
+---------------------------------------------------------------+
                        mt-2 (gap between cards)
+---------------------------------------------------------------+
| [Guidance banner - NEW]                                        |
| p-3 rounded bg-charcoal-dark border-amber-700/50              |
|                                                                |
|   "Registry Required for BLS Registration"                     |
|   text-amber-400 text-xs font-semibold mb-1                   |
|                                                                |
|   "To register your BLS key on-chain, add this service's..."  |
|   text-tan-muted text-xs                                       |
+---------------------------------------------------------------+
```

The guidance banner renders INSIDE the `{serviceBls && (...)}` block, AFTER the existing BLS Operator Key card, and BEFORE the actions bar. It uses `mt-2` to separate from the key card above.
