# Phase 10 -- UI Design Contract

> Visual and interaction contract for the P2P Operator Dashboard. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|

## Color

All colors are from the existing `tailwind.config.js` palette. No new colors introduced.

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant (60%) | `charcoal-darkest` | #1E1E1E | Page background (inherited from `body` CSS) |
| Secondary (30%) | `charcoal-medium` | #2D2A2A | Card backgrounds (`bg-charcoal-medium`) |
| Card border | `charcoal-light` | #383232 | Card borders (`border-charcoal-light`) |
| Nested surface | `charcoal-dark` | #222020 | Nested items within cards (peer list rows, service rows) |
| Primary text | `beige-warm` | #CEC3B7 | Body text, values, peer IDs |
| Heading text | `beige-light` | #DDD2C6 | Page title, card section headings |
| Muted text | `tan-muted` | #A89F96 | Labels, secondary info, timestamps, empty state text |
| Accent (10%) | `success-600` | #52B79D | "Registered" badge background, online status dot, connected peer indicator |
| Warning | `yellow-500` (Tailwind built-in) | #EAB308 | "Loading" pulse animation on status dots |
| Destructive | `red-3` | #A7656F | "Unregistered" badge text, error messages |
| Error background | `red-900/20` + `red-800` border | -- | Error alert container (matches Health.tsx error pattern) |

Primary visual anchor: the page title ("P2P Network") and the Node Identity card, which sits at the top of the content area and orients the operator to their node's network identity.

Accent reserved for:
- Status dots indicating "online" / "connected" state (`bg-success-600`)
- "Registered" badge on operator keys (`bg-success-900/30` background with `text-success-500` text)
- Copy-success checkmark icon (`text-green-4` -- existing pattern in AddressDisplay)

### Layout Rules

- Page container: `flex flex-col gap-6 max-h-[calc(100vh-12rem)] overflow-y-auto pr-2` (matches Health.tsx)
- Cards: `p-6 rounded-lg bg-charcoal-medium border border-charcoal-light` (matches Health.tsx cards)
- Nested rows within cards: `p-3 rounded bg-charcoal-dark border border-charcoal-light` (matches `ChainHealthItem`)
- Page header row: `flex items-center justify-between` with title left, refresh controls right
- Card section headings: left-aligned with `mb-4` below
- Grid layout for identity fields: `grid grid-cols-2 gap-4` for peer ID + discovery mode side by side
- Listen addresses: full width (`col-span-2`), stacked vertically with `flex flex-col gap-1`
- Service operator rows: stacked with `flex flex-col gap-2` inside the services card

## Interaction Contract

### Polling

| Property | Value |
|----------|-------|
| Auto-refresh interval | 15000ms (15 seconds) |
| Refresh on mount | Yes |
| Manual refresh | "Refresh Status" button in page header |
| Visual feedback during refresh | Button text changes to "Refreshing..." + `disabled` state |
| What is polled | `cmd_get_p2p_status` (P2P status) |
| What is NOT polled | On-chain registration checks (too expensive for auto-poll) |

### On-Chain Registration Check (P2P-05)

| Property | Value |
|----------|-------|
| Trigger | On initial page mount only + manual refresh |
| Per-service | One `readContract` call per EVM service with known registry |
| Cosmos services | Show "N/A" badge (no registration check for non-EVM) |
| Cache | Store in local `useState` alongside P2P status -- reset on manual refresh |
| Error handling | On failure, show "Unknown" badge (do not break the page) |

### Copy-to-Clipboard

| Property | Value |
|----------|-------|
| Component | `AddressDisplay` (reused) |
| Truncation | Default `first6...last4` for all key types (ECDSA and BLS) |
| Hover | Copy icon appears on hover (existing behavior) |
| Confirmation | Checkmark icon for 1.5 seconds (existing behavior) |
| Full value | Accessible via `title` attribute on hover (existing behavior) |

### P2P Disabled State

| Condition | `P2pStatus.enabled === false` |
|-----------|-------------------------------|
| Display | Single card spanning full width |
| Content | Icon + "P2P Networking Disabled" heading + "This node is running in single-operator mode. P2P features require enabling local or remote discovery in the WAVS configuration." body |
| Sections hidden | Peers card, Services card are NOT rendered |
| Identity card | Still rendered (shows that P2P is disabled with no peer ID) |

### WAVS Not Running State

| Condition | `cmd_get_p2p_status` throws `AppError::WavsNotRunning` |
|-----------|-------------------------------------------------------|
| Display | Single error card |
| Content | "WAVS node is not running" heading + "Start the WAVS node to view P2P network status." body |
| Retry | Auto-retry on next polling interval (15s) |

### Stretch Goal: P2P-06 Quorum Progress

| Property | Value |
|----------|-------|
| Implementation | Placeholder only -- no backend endpoint exists |
| Display | Within each service operator row, show muted text: "Quorum data not available" |
| Visibility | Only render if stretch feature is enabled (a simple boolean flag, default `false`) |

## State Mapping

| UI Element | Data Source | Update Mechanism |
|------------|------------|------------------|
| Peer ID, discovery mode, addresses | `cmd_get_p2p_status` -> `P2pStatus` | 15s polling interval |
| Connected peers count | `P2pStatus.connected_peers` | 15s polling interval |
| Peer ID list | `P2pStatus.peer_ids` | 15s polling interval |
| Subscribed service hashes | `P2pStatus.subscribed_services` | 15s polling interval |
| Service human-readable names | `appStore.services.get(hash)?.name` | Zustand store (already populated) |
| Operator signing key per service | `cmd_get_service_signer` -> `SignerResponse` | On mount + manual refresh |
| On-chain registration status | `POAStakeRegistry.getLatestOperatorSigningKey` via Viem | On mount + manual refresh |

## P2P Nav Icon Specification

SVG icon for the header nav, following the existing icon conventions (14x14 viewBox, `fill="currentColor"`):

- Concept: Three nodes (circles) connected by lines, forming a simple network topology
- Three circles at positions forming a triangle: top-center, bottom-left, bottom-right
- Lines connecting all three nodes
- Circle radius: 2
- Line strokeWidth: 1.4
- Use `stroke="currentColor"` for lines, `fill="currentColor"` for circles
